1. VISÃO GERAL DO PROJETO
════════════════════════════════════════════════════════════════════════════════

OBJETIVO
Criar uma plataforma Bloomberg-estilo (terminal financeiro) para análise de 
oportunidades de leilão imobiliário, inteligência de mercado, e ferramentas 
de investimento. Ao mesmo tempo, servir como hub para promover o livro 
"A Bíblia do Leilão Imobiliário".

POSICIONAMENTO
"Hercleus Terminal: Bloomberg para Investidores Imobiliários Brasileiros"
- Dados em tempo real de leilões
- Analytics e visualizações avançadas
- Comunidade de investidores
- Conteúdo educacional do livro
- Ferramenta de análise de ROI

DIFERENCIAL
✓ Foco específico em auctions (não competição direta com Bloomberg)
✓ Integrado com conteúdo do livro (gera tráfego e autoridade)
✓ Comunidade de usuários (rede de efeito)
✓ Modelo freemium (Free + Premium)
✓ Monetização: Assinatura + Dados + Serviços

TIMELINE
MVP (Mínimo Viável): 6-8 meses
Full Platform: 12-18 meses
Scale: 24+ meses

ORÇAMENTO TOTAL
Fase 1 (MVP): R$ 60.000-100.000
Fase 2 (Full): R$ 150.000-250.000
Fase 3 (Scale): R$ 300.000+

2. ARQUITETURA TÉCNICA E STACK DE TECNOLOGIA
════════════════════════════════════════════════════════════════════════════════

FRONTEND (Interface do Usuário)
┌─────────────────────────────────────────────────────────────┐
│ Framework: React.js + TypeScript                            │
│ UI Library: Material-UI (MUI) ou Tailwind CSS               │
│ Real-time: WebSockets (Socket.io)                           │
│ Charting: Chart.js + Recharts (similar Bloomberg)           │
│ Dashboard: Custom built com React Grid                      │
│ Mobile: React Native ou Progressive Web App                 │
└─────────────────────────────────────────────────────────────┘

BACKEND (Servidor)
┌─────────────────────────────────────────────────────────────┐
│ Linguagem: Python (Django/FastAPI) ou Node.js (Express)     │
│ API: RESTful + GraphQL (para queries complexas)             │
│ Real-time: WebSocket server (Node.js Socket.io)             │
│ Cache: Redis (performance de dados)                         │
│ Message Queue: RabbitMQ ou Celery (processamento)           │
│ Search: Elasticsearch (full-text search de leilões)         │
└─────────────────────────────────────────────────────────────┘

DATABASE (Armazenamento)
┌─────────────────────────────────────────────────────────────┐
│ Principal: PostgreSQL (dados estruturados)                  │
│ Time-series: TimescaleDB (histórico de preços)              │
│ Cache: Redis (sessões, dados quentes)                       │
│ Search: Elasticsearch (índice de leilões)                   │
│ Backup: AWS S3 ou Google Cloud Storage                      │
└─────────────────────────────────────────────────────────────┘

INFRAESTRUTURA (Cloud)
┌─────────────────────────────────────────────────────────────┐
│ Hosting: AWS (EC2, RDS, S3, Lambda) ou Google Cloud         │
│ Container: Docker + Kubernetes (escalabilidade)             │
│ CI/CD: GitHub Actions ou GitLab CI                          │
│ CDN: CloudFlare (performance global)                        │
│ Monitoring: New Relic ou DataDog                            │
│ SSL: Let's Encrypt (HTTPS automático)                       │
└─────────────────────────────────────────────────────────────┘

INTEGRAÇÃO DE DADOS
┌─────────────────────────────────────────────────────────────┐
│ Raspagem Web: Scrapy + Beautiful Soup (coleta de editais)   │
│ API Jud: Integração com portais de tribunais                │
│ APIs Externas: FipeZap, Zap Imóveis, VivaReal               │
│ Dados Estruturados: CSV/JSON (leiloeiros)                   │
│ Cache Real-time: Atualização a cada 6 horas                 │
└─────────────────────────────────────────────────────────────┘
